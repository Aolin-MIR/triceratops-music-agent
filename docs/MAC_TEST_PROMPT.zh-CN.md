必须遵守：

- 修改代码前先确认精确文件位置；修改后先做语法 / 类型 / 构建检查，再运行相关测试和真实功能。

一、先记录机器和环境
记录芯片、CPU 核数、统一内存、macOS 版本、可用磁盘、REAPER 版本 / 架构、Python 版本 / 路径 / 架构。确认 Apple Silicon、macOS 14+ 和原生 ARM64 Python 3.10 / 3.11，排查 Rosetta 混用。
当前脚本默认 python3.11、device=cpu。先验证这条发行路径；不要因为 MPS 可用就把整个产品标为 GPU 加速成功。Intel Mac 或不满足系统条件时保留诊断，停止不适用的安装步骤，不能声称受支持。

二、从用户拿到的 ZIP 开始安装
核对发行校验清单（如有），记录本次下载哈希。解压到稳定路径并保留目录，运行 setup-macos.sh，确认独立 venv、依赖原生架构、固定模型下载 / 校验和 doctor。检查路径含空格 / 中文、重复执行安装、已有模型复用和下载失败后的明确报错。核对 VST3 实际扫描位置，避免重复版本导致测试错包。留存 doctor 输出，但 doctor 通过不等于功能通过。
如果安装失败，先定位真实缺失依赖、wheel / 架构 / 签名问题并修好，不要转而只测开发环境。

三、真实打开 REAPER 和插件
新建并保存 Triceratops-Mac-Test 工程，扫描并插入 Triceratops，确认本地后端能自动启动、界面状态正确、按钮可交互。切换中文 / English，检查按钮、提示、状态、操作结果；关闭重开检查语言保存。
使用我配置的聊天 API 测试自然中文和英文：
1. “阴天傍晚的钢琴，留一点空白，不要鼓。”
2. “接着选中的片段再写四小节。”
3. “节奏收紧一点，旋律别变。”
记录实际工具选择 / 参数 / 返回结果；回答一段文字而未执行操作不能算成功。API 不支持工具调用、超时或额度失败，要明确归因，不能归为模型生成成功。

四、逐项验证并检查实际文件和宿主结果
1. 新建 MIDI：实际调用固定 MIDI-LLM；检查文件可解析、音符非空、各声部 / 时长 / 节拍，以及请求的乐器、调性和“不要鼓”是否遵守。功能成功和音乐语义符合率分别记录。
2. 导入：分别测试显式 Import 和 Auto-Import。必须看到 MIDI item 真正出现在 REAPER 轨道上，打开钢琴卷帘确认音符。加载可用音源并实际播放，录制或导出短试听，不能把 MIDI 无自带音色误判为模型坏了。
3. MIDI 编辑：量化、力度和转调分别核对前后事件；要求保留旋律时检查音高 / 旋律事件不变，检查不受该操作影响的事件。
4. MIDI-GPT 续写：在短的自有测试片段后追加四小节，逐事件比较原片段的时间、音高、力度、通道等；新增内容不能只复制原片段，不能只延长 item。
5. 填充：明确指定轨道和小节，用 MIDI-GPT 填充，检查修改范围之外的事件保留。
6. HTDemucs 四分轨：使用获授权的短混音输入，产生 vocals / drums / bass / other 四个可解析音频；检查长度、采样率和是否异常静音，实际导入四条 REAPER 轨道并试听。根据源素材判断正常的空声部，不把四个文件存在当作质量通过。
7. Basic Pitch ONNX 转 MIDI：用自有单旋律音频，实际转写、导入并检查音符。复杂混音另列模型局限，不能承诺完美转写。记录实际 ONNX providers。
8. 音频分析：验证时长、速度 / 调性估计、起音和分段。用已知节奏音频核对速度；静音、空输入、过长输入和错误路径需明确报错或明确说明截取范围。
9. Rec MIDI / Rec audio：实际从宿主路由输入并录制，核对生成文件与输入一致。没有实体设备时可从 REAPER 中的自有 MIDI 和音频素材路由，不能虚构录制成功。
10. Keep / Reject / Undo、任务状态 / 取消：检查真实反馈保存和版本恢复范围；Undo 不能误删用户宿主轨道；取消后确认任务和子进程确实结束。重开插件检查不会误恢复为正在生成或卡在忙碌状态。
11. 记忆 / RAG：用专用测试偏好和本地知识条目，重开后读取并检索；更新 / 删除后验证实际持久化结果。不要仅凭聊天模型声称“记住了”。
12. 错误路径：缺模型、API 无效、离线、无 MIDI 选中、重复点击、后端退出、REAPER 重开。检查准确错误、界面恢复、子进程清理；避免操作真实私人配置，使用测试配置副本。

五、性能和内存
每种模型至少完成一次冷启动和一次重复任务，标明 token 上限、音频时长、声道、采样率和操作步骤。记录加载 / 任务总耗时、输出时长 / 音符数、模型相关全部子进程的内存观测、系统内存压力和 swap 增量。RSS 不能直接当作精确的统一内存峰值，应说明采样方式、共享页和测量限制。
先完成默认 CPU 基线。若硬件允许，再作为单独修复 / 验证任务检查 MPS；每个音乐模型分别确认实际设备和算子，不允许 PyTorch MPS 算子静默落到 CPU 后仍声称全 GPU 成功。MPS 不可用可以保留明确失败与 CPU 基线，不能把未经测试的加速宣传为已支持。不要求引入 MLX 或更换音乐模型。
在现有 REAPER 工程带合理音源负载时复测短任务；出现内存压力或 OOM 要记录任务条件。只对这台 Mac 给出结论，不把一次 16 GB / 24 GB / 32 GB 实测外推为所有机型的最低配置。
